# Shama Sale Record

A browser-based sales, expenses, invoices, debts, inventory and reporting tool.

## Files
- `index.html` — website structure
- `styles.css` — responsive styling
- `app.js` — application functionality and browser storage

## Publish with GitHub Pages

1. Sign in to GitHub and create a **new public repository**, for example `shama-sale-record`.
2. On the repository page, choose **Add file → Upload files**.
3. Upload `index.html`, `styles.css`, and `app.js` from this folder. Keep all three files in the repository root (not inside another folder).
4. Enter a commit message such as `Add Shama Sale Record website`, then click **Commit changes**.
5. Open the repository's **Settings → Pages**.
6. Under **Build and deployment**, choose **Deploy from a branch**.
7. Select branch **main** and folder **/(root)**, then click **Save**.
8. Wait for GitHub Pages to publish. Refresh the Pages settings page; GitHub will show the public website address. It will usually look like:
   `https://YOUR-GITHUB-USERNAME.github.io/shama-sale-record/`
9. Open that address on your phone or computer. You can bookmark it or add it to your phone home screen.

## Important data and backup notes

- This app stores its records in the browser's local storage on the device/browser being used.
- Publishing the website does **not** create a shared online database. Records entered on one device will not automatically appear on another device.
- Do not clear browser/site data or use private/incognito browsing for normal record keeping.
- Use **Reports & Backup → Download full backup (JSON)** regularly and keep a copy somewhere safe.
- To move records to another browser/device, open the website there and use **Restore a previous backup**.
- GitHub Pages hosts the website files publicly. Do not put private customer records or backup files in the GitHub repository.

## Updating the website

Edit the relevant file, upload the replacement to the same repository path, and commit the changes. GitHub Pages will publish the update automatically after its deployment finishes.
